# Create a journey from GPX or details

**Current design · 24 November 2026.** Dashboard and Journeys open **Create a journey**. On web, the GPX picker leads and **Enter details without GPX** in the page header opens the schedule form in place. Native offers **Upload GPX** and **Enter details**. The available recording determines the method. Pending saves reopen the method that owns the attempt, and explicit planning handoffs can open the schedule form directly. [Earlier stage-first exploration](journey-creation-workflow.html) · [Existing batch import](create-journey-gpx-redesign.md)

## Layout and copy

Start web creation with a spacious Fold dropzone. On a drag, highlight the target and change the prompt to **Release to add files**. Use picker instructions on coarse-pointer devices. After selection, the compact **Add files** target stays available above file status and transfer controls. Once a recording is ready, show one review panel with the title across the top. **Edit title** opens a field in place and becomes **Done** in the same header position. Give the route most of the width. Put the recorded times, People and Recordings alongside it, and keep the privacy label and Save together in the footer. Stack these sections in the same reading order on narrow screens.

**Recordings** starts open and can be collapsed from its heading. **Add files** remains available and reopens the list on selection. Up to three recordings fit without a list scrollbar. Four or more use a fixed-height list. Show the sections for one recording at a time in a compact inset with a short section heading, measurements and recorded times. Keep longer section lists scrollable and put keyboard focus at the start of a new page. Long recipient lists scroll inside the invitation dialog before and after the save.

**Route stats** below the map shows recorded distance, elapsed time, elevation gain and elevation range. It stays visible when the outlined **Hide map** button collapses the map. Show the recorded section count when a distance total is unavailable. In the schedule form, group the title and schedule, keep the end date optional, and use the existing invitation handoff. ## State and recovery

| State | What appears | Next action |
| --- | --- | --- |
| Opening | A brief check for a pending save or staged files. If recovery cannot be checked, show the failed check beside its retry. | Resume the existing attempt or select a creation method. |
| Empty | **Add GPX files**, file limits, drag-and-drop or picker, and a visible way to enter details. | Choose files or switch methods. |
| Files selected locally | Name, size, **On this device**, and **Remove** on each row. Additional selections append. | **Upload for review** starts transfer. Inline rejection messages leave valid siblings in the list. |
| Uploading | Queued and transferring labels and acknowledged-byte progress when available. | **Pause upload** keeps received parts. Other methods stay closed during transfer. |
| Paused or interrupted | A resumable upload shows **Resume upload**. A file that is no longer available locally shows **Choose original file**. | Resume, reselect, remove, or enter details. |
| Reading or partly ready | Rows show processing and ready states separately. Draw the ready routes as they arrive. The save action waits for all remaining files to pass review. | Wait, retry processing if offered, or remove an unwanted file. |
| Needs attention | Describe the problem at the file. Rejected GPX content can be removed and replaced. A failed processing or status request can be tried again. A stale batch review offers a refresh, and the map shows geometry matching the reviewed revisions. The web draft warns when temporary files have an hour or less left. A missing recovered draft prompts the user to choose files again. | **Retry reading**, **Check again**, **Refresh recordings**, or **Remove**, as applicable. |
| Ready | Recorded tracks and a route summary, an editable suggested title, recorded times and timezone when available, and a visible file list with expandable sections. Use the route-only overview if a basemap is unavailable. Untimed tracks can be saved without dates. | **Create journey** on web opens its detail page. |
| Invite people on web | Open a dialog from the People row. Look up opted-in Kairn members or add recipients by email. The recording batch limits who can use its search and which saved journey can use its selections. | **Send invitations** saves the journey and starts delivery in the background. The dialog closes on the creation screen and a toast confirms delivery was queued. Reopen **Invite people** to review delivery status, cancel outstanding invitations, or send invitations to recipients listed under **Not sent yet**. **Open journey** opens the saved journey when selected. |
| Save or recovery | Keep the title and route visible in the current web session while saving. An unconfirmed save offers **Retry save** in the footer or **Retry send** in the invitation dialog. On reload, the stored request can be retried even when staged files have already been committed. | Retry recovers the original journey if the server already committed it. |
| Invitation delivery | The main **Create journey** action opens the saved journey as soon as it is saved and queues any selected invitations in the background. | If confirmation is interrupted, **Retry invitations** in the creation dialog or journey detail reuses the saved request. |
| Enter details | Title, start date/time, timezone, and optional end. Invalid fields keep their values and expose errors beside the field. | **Save journey** or **Create & invite people**. |

Switching methods retains each panel’s edits and the staged files while the page is open. Uploaded files and pending save receipts use their existing recovery rules after reload or relaunch. A web file selected before transfer stays in memory during that visit. Both clients use their existing private creation and recording endpoints, including expiry and account boundaries. Historic single-recording imports retain their resume entry. [GPX recovery and limits](create-journey-gpx-redesign.md#file-selection-and-upload)

## Saved journey map

The GPX-enabled web build opens a compact title and metadata header followed by the saved route map. **View people** opens the reusable People dialog from both journey layouts. It contains members, roles, invitations, and leave and removal actions. Account-bound sign-in handoffs from the retired People route resolve to Journey details.

The **Recordings** disclosure lists each GPX file with its section count and access. **Details** opens section measurements and access actions in a dialog. **Add recording** opens upload and review for the current journey and refreshes the file list and combined map after attachment. The standalone import remains available from Account and import recovery. A legacy Add recording link opens the dialog from Journey details, and an explicit pending legacy import can finish its original workflow.

The combined map uses the same permission checks as each recording. It prioritizes recent recording data and marks the overview when it omits sections to bound the payload.

The map starts in Mapbox Outdoors and offers Satellite Streets, with zoom and a fit-to-route control. Set `VITE_MAPBOX_PUBLIC_TOKEN` to a public `pk.` token in `apps/web/.env.local` and rebuild the web preview. Use a public token with the map read scopes and restrict deployed tokens to the application URLs. Without a usable token, the saved geometry still draws as a route-only overview. [Mapbox token setup](https://docs.mapbox.com/help/dive-deeper/access-tokens/)
