# Kairn repository instructions

- Start with [implementation progress](docs/progress.md) to find the current milestone, its implementation plan, verified work, and pending decisions. Use the [documentation index](docs/README.md) to find the core planning references. Follow the [requirements](docs/core/product-requirements.md) for product scope and the [architecture](docs/core/architecture.md) for boundaries.
- The iOS and Android apps are frozen until the user explicitly resumes mobile work after web validation. Keep implementation and verification focused on web and its supporting services. Do not edit or revert mobile source, config, or native tests, run mobile builds, boot test devices, or start Metro or mobile-only services. Preserve the existing mobile work for when development resumes.
- Use one backend and one versioned API contract for web, iOS, and Android. Put business rules, permissions, processing, and persisted state in the shared backend. Clients submit inputs and render API responses through `@kairn/contracts`. Keep existing callers compatible, avoid web-only endpoints for shared features, and run `pnpm api:check` and the relevant backend integration tests for contract changes. See [HTTP contracts](docs/core/architecture.md#91-http-contracts).
- Update [implementation progress](docs/progress.md) in the same change when a milestone starts, completes, changes direction, or hits a material blocker. Record the next concrete step and the actual validation result, with links to durable evidence. Keep it short and use Git history for older status.
- Keep automated regression checks and reusable fixtures under `tests/`. Keep test-only routes out of application bundles.
- For web UI, follow [Fold](DESIGN.md), use the shadcn Base UI registry (`base-nova`), import the owned primitives from `@/components/ui/`, and update the `/design-system` catalog when a shared component changes.
