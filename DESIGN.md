# Fold · Kairn design system

Fold is the design contract for the web application. Open **/design-system** in the running web app to inspect System, Light, Dark and Outdoor appearances. The catalog renders the same React exports as production screens. Use it to review one primitive at a time. [Web component source](apps/web/src/components/ui/) · [Catalog route](apps/web/src/routes/design-system.tsx)

## Build a screen

The web registry uses shadcn **base-nova** with Base UI React. Generate from the Base registry and keep its behavior behind our owned exports. Import the owned component from `@/components/ui/<file>`. Keep interaction state, data and permissions in the caller. Put a change to every instance in the primitive. Use a variant for a recurring difference in purpose, and use a caller’s `className` for layout within its parent. Include each new family and its meaningful states in the catalog.

```tsx
import { Button } from "@/components/ui/button";
import { Field, FieldLabel } from "@/components/ui/field";
import { Input } from "@/components/ui/input";

<form onSubmit={saveJourney}>
  <Field>
    <FieldLabel htmlFor="title">Journey name</FieldLabel>
    <Input id="title" name="title" required />
  </Field>
  <Button
    type="submit"
    disabled={saving}
    feedback={saving ? "pending" : "idle"}
  >
    {saving ? "Saving…" : "Save journey"}
  </Button>
</form>;
```

Use `<ButtonLink render={<Link to="/journeys" />}>Open journeys</ButtonLink>` for navigation styled as an action. The anchor retains link semantics. Give icon-only buttons a specific accessible name. Keep buttons inside forms explicit about their type.

| Role                   | Light                 | Dark                  | Use                                                  |
| ---------------------- | --------------------- | --------------------- | ---------------------------------------------------- |
| Canvas                 | `#FBFAF6`             | `#1B1D1A`             | Page background                                      |
| Surface                | `#FFFEFA`             | `#252823`             | Fields, cards, menus, sheets                         |
| Receipt face / text    | `#20221D` / `#FFFEFA` | `#F1F2E7` / `#252823` | Floating confirmation, including its dismiss control |
| Rail                   | `#F3F2EC`             | `#171916`             | Persistent navigation                                |
| Ink                    | `#20221D`             | `#F1F2E7`             | Body and headings                                    |
| Secondary text         | `#61645A`             | `#BDC0B3`             | Metadata and help                                    |
| Divider / control edge | `#D9DBD0` / `#787C6F` | `#42473D` / `#919786` | Fine panel separation and stronger field outlines    |
| Primary face / text    | `#24271F` / `#FFFEF8` | `#D3F477` / `#1C2315` | One committing action per group                      |

| Focus                  | `#4F6334`             | `#D3F477`             | Visible keyboard focus                               |
| Error / success        | `#A53126` / `#3B602C` | `#FFA49C` / `#B5DF9D` | Pair colour with a label or icon                     |

Use semantic utilities such as `bg-card`, `border-input`, `text-muted-foreground` and `text-destructive`. Citron marks selection. Lilac and clay distinguish studies and attribution. The role values live in the [web theme](apps/web/src/fold.css) and [Tailwind mappings](apps/web/src/index.css). The root appearance preference applies to portals and the server-rendered reader. Outdoor uses opaque surfaces, strong boundaries and the existing high-contrast palette.

- **Type.** Bricolage Grotesque for interface headings, Source Sans 3 for controls and body. Use 16 px body text, 15–16 px controls and 14 px metadata. Keep the reader’s Georgia chapter headings and adjustable reading size. Use rem for scalable text.
- **Spacing.** Use 4 px from label to value, 8 px between related controls, 12 px between examples, 16 px for group insets and 24 px between tasks. Fold cards use 12 px internally or 8 px for a compact card. Use `p-inset` for a form or panel group and `gap-section` between tasks. Tailwind spacing multiples use the shared 4 px step. Rows can grow when content wraps.
- **Shape.** Use a 6 px radius on fields and controls, 10 px on panels, and a 3 px radius on the button key. Use an outline on editable fields, fine borders on groups and restrained elevation for overlays.
- **Targets.** A default pointer control starts at 34 px. Compact and large sizes have distinct minimums. Reserve at least 48 CSS px for coarse-pointer primary controls and choice labels. Outdoor provides a 44 px minimum with a fine pointer. Keep field capture actions at least 56 units on their applicable platforms.
- **Motion.** Compress the action key on press and keep focus in place on status changes. Use brief state transitions. Honour reduced motion and expose the result through text and semantics.

## Feedback, icons and motion

| Situation                          | Fold treatment                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Completed optional action          | Call `useReceiptToast()` after confirmation from the operation. A five-second receipt uses the theme’s ink as its background and surface colour for its label and dismiss control. Place the check in an Inset key at the lower trailing edge of the page alongside the message. Repeating it refreshes one receipt. Focus stays at the action. [Base UI Toast](https://base-ui.com/react/components/toast) |
| Correction or recovery             | Place field validation beside the field. Keep failed requests, retry actions, pending sync and access changes visible inline until resolved. Use a progress bar only when the amount is known.                                                                                                                                                                                                              |
| Choosing from a short list         | Use `NativeSelect` with a visible label. Fold styles the closed field and the browser supplies the picker, touch interface and keyboard input.                                                                                                                                                                                                                                                              |
| Changing sort or issuing a command | Use `DropdownMenu`. Group mutually exclusive options as radio items, show a check beside the current value, and return focus on dismissal. [shadcn Base Dropdown Menu](https://ui.shadcn.com/docs/components/base/dropdown-menu)                                                                                                                                                                            |
| Empty journey collection           | Render `JourneyMap` beside a heading and a real next action after the collection loads empty. Use the three paper panels, dashed route, contour lines and theme ink. Keep this decorative print hidden from assistive technology. Filtered results and errors need their own explanation.                                                                                                                   |
| Waiting for the application        | The launch mark and “Opening Kairn…” appear when bootstrap or route loading takes over 200 ms. Show content as soon as ready. The native launch-screen design uses the resting mark on the matching canvas and hands off immediately when ready.                                                                                                                                                            |
| Waiting within the workspace       | Preserve the page heading and existing content when possible. Use `ContentLoading` for a missing region, with a task-specific label, a three-pleat activity mark and two static skeleton rows. Use the same mark in a pending primary button.                                                                                                                                                               |

Use Lucide for recognizable controls, navigation and state. Import individual icons at 16–20 px, keep their consistent outlines and inherit the foreground colour. Give icon-only actions a text alternative on the control. For a new domain concept, first try an existing glyph with a visible label. Draw a custom glyph only when a distinct meaning or identity requires it. Use a 24-unit grid, 2-unit strokes and rounded joins for utility icons. The three-pleat Fold mark is the brand exception. Add a named export and a catalog specimen for each new custom glyph. [Lucide design guide](https://lucide.dev/guide/design/icon-design-guide)

Use motion to identify the control or surface that changed. The Inset key compresses on press. Checkboxes and radios compress on press, including presses on their labels, and settle slightly larger when checked. Quiet buttons compress slightly. Switch thumbs move between endpoints, sort chevrons turn on opening, and overlays use brief entrances. The open chevron retains its orientation under reduced motion. Disabled actions keep a resting key, including when they retain focus after completion. A receipt moves a few pixels and fades. The three pleats pulse three times, then rest while the loading label remains visible. Text edits, checked values, tab focus, tables and artwork respond immediately. Prefer CSS opacity and transform transitions around 100–180 ms. Under reduced motion, use the resting mark and apply state changes immediately. Preserve the same text, focus destinations and selection cues.

## Review a change

1. Edit the primitive, then exercise it on a real caller and on `/design-system`. Preserve refs, form attributes, keyboard behavior, and Base UI `render` composition.
2. Review default, hover, pressed, focus, disabled, and applicable pending, success and invalid states. Include long labels, an input error and a populated row. Compare light, dark and outdoor with the same draft or selection.
3. At 320 CSS px and 200% text, check wrap, focus visibility, reachable actions and a scrollable overlay. Ordinary text needs 4.5:1 contrast. Large text, essential control boundaries and selection indicators need 3:1.
4. Keep durable versus pending saves, access scope, provenance and route uncertainty explicit. Pair solid recorded paths and dashed estimates with text and an equivalent stage list. Apply privacy changes to visible and accessible content together. [Journey interactions](docs/core/journey-interactions.md)
5. Run the web build, the [catalog regressions](tests/web/fold-atlas.playwright.ts) and checks for the affected production flow. Update this file and the catalog when a shared component contract changes.

### Accessibility acceptance

- Include the visible control label in its accessible name. An icon-only control needs an action name, and decorative icons or duplicate avatar initials should be hidden from assistive technology. Name controls with text that makes sense when read on its own. [WCAG label in name](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) · [Lucide accessibility](https://lucide.dev/how-to/accessibility)
- Mark a field and its control invalid together. Connect the message with `aria-describedby`, keep applicable help text in the description, and focus the first invalid field on a custom submit. Give reusable instances their own IDs. Keep required, optional and read-only states distinguishable wherever a form mixes them. [shadcn Field](https://ui.shadcn.com/docs/components/base/field) · [React useId](https://react.dev/reference/react/useId)
- Use one current destination per navigation group. Preserve arrow-key navigation in tabs and menus. A modal traps focus, has a visible close action, and returns focus to its invoker or the selected destination. A keyboard shortcut remembers the invoking control. [WAI-ARIA tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) · [Base UI Dialog](https://base-ui.com/react/components/dialog) · [shadcn Base Dropdown Menu](https://ui.shadcn.com/docs/components/base/dropdown-menu)
- Check system colour changes, forced colours, reduced motion and 200% text. Selection needs a visible cue when the OS replaces background colours. Open popovers, sheets and dialogs during the audit. Run WCAG 2.2 A/AA automated checks and verify keyboard operation. Record screen-reader and physical-device testing separately. [Tailwind state variants](https://tailwindcss.com/docs/hover-focus-and-other-states) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [Playwright accessibility testing](https://playwright.dev/docs/accessibility-testing)

See the [web component review](docs/design-system/web-component-review.md) for the inventory, findings and remaining manual checks.

## Native adoption

The current milestone ships responsive web controls. The mobile milestone starts with buttons, text entry and the journey picker in Expo. Move approved cross-platform roles into the [shared token sources](packages/design-tokens/tokens/) and regenerate the bindings with `pnpm tokens:generate`. The existing native consumers continue to use the shared palette until that migration. Match role, hierarchy and state names across clients. Use native pickers, sheets, Back behavior, accessibility traits and text scaling. Verify 44 pt on iPhone, 48 dp on Android and 56 units for primary capture. Test large text, focus restoration, outdoor legibility and one-handed reach on devices before rollout.
